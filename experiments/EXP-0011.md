# EXP-0011 — Additive vs boolean attention masks on DirectML

**Date:** 2026-09-30
**Status:** COMPLETE — boolean masks rejected

## Question

Why did `masked_fill` fail on DirectML, and what is the correct fix?

## Method

Isolated operator probes, then a full forward pass with each approach.

## Result

| Operation | Result |
|---|---|
| `bitwise_or` on different-shaped bool tensors | OK |
| `logical_or` | OK |
| `~` (invert) | OK |
| `torch.where` | OK |
| Comparison → 2-D bool | OK |
| `masked_fill` with a **literal** bool mask | OK |
| `masked_fill` with a **computed** 4-D bool mask | **`RuntimeError: m_device->CreateOperator`** |

The failure is specific: DirectML's shader compiler cannot materialise a boolean tensor
produced by a multi-operator computation, when the consumer is `masked_fill`. It compiles the
same tensor when it is a literal.

## Fix

Replace boolean masks with **additive float masks**: `0` where attention is allowed, a large
negative value where it is forbidden, added to the scores.

```python
def causal_mask(seq_q, seq_k, device, dtype, kv_offset=0, min_value=None):
    q_idx = torch.arange(seq_q, device=device).unsqueeze(1) + kv_offset
    k_idx = torch.arange(seq_k, device=device).unsqueeze(0)
    mask = torch.zeros((seq_q, seq_k), dtype=torch.float32, device=device)
    mask.masked_fill_(k_idx > q_idx, neg)      # in-place on a 2-D tensor: supported
    return mask.to(dtype).view(1, 1, seq_q, seq_k)
```

## Interpretation

The additive form is better on three axes, not just as a workaround:

1. **Portability** — addition is implemented everywhere.
2. **Speed** — one fewer kernel; `masked_fill` is a read-modify-write.
3. **Numerics** — identical, because the masked entries collapse to the same value inside
   the fp32 softmax either way.

Padding masks are summed rather than OR-ed for the same reason.
