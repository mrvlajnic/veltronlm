# EXP-0001 — GPU backend provisioning and throughput measurement

**Date:** 2026-09-30
**Status:** COMPLETE (with one measurement error corrected)
**Hardware:** AMD Radeon RX 6700 XT (12 GiB), Intel i7-7700, Windows 11

## Question

Is the RX 6700 XT usable as a PyTorch training device on Windows, and what is its real
throughput?

## Method

`nvidia-smi` is absent (expected for AMD). ROCm is not installed. The viable path is
`torch-directml`, which PyTorch exposes as the generic `privateuseone` device type.

```
pip install torch==2.4.1 --index-url https://download.pytorch.org/whl/cpu
pip install torch-directml==0.2.5.dev240914 --no-deps
```

`torch-directml` **pins** `torch==2.4.1`; installing with dependencies silently changes the
torch version.

## Result

### A measurement error, corrected

The first benchmark reported **53.156 TFLOP/s** for fp16. That was wrong: the result buffer
was read with `.cpu()` but **not** inside the timing loop, so it measured queue submission
rather than computation.

With a blocking read on every iteration:

| Backend | dtype | n | TFLOP/s |
|---|---|---:|---:|
| DirectML | fp32 | 2048 | 1.759 |
| DirectML | fp16 | 2048 | **2.798** |
| CPU (8 threads) | fp32 | 2048 | 0.081 |
| CPU (8 threads) | fp32 | 1024 | 0.176 |

The unsynchronised figure was **19x too high**. Every throughput number in this repository
uses the synchronised path.

### Operator support

All operations required by the architecture were verified end to end:

`nn.Embedding`, `F.embedding`, `softmax`, `masked_fill`, `SiLU`, manual RMSNorm, RoPE,
`repeat_interleave` (GQA), `cross_entropy`, `AdamW.step`, `clip_grad_norm_`, and a complete
Transformer block forward+backward in both fp32 and fp16.

### Three limitations, each of which changed the design

| Limitation | Response in the code |
|---|---|
| No `aten::embedding` under autocast | `torch.autocast` is used **only** on CUDA. On DirectML, fp16 = `model.half()`. |
| Cannot materialise a computed 4-D bool tensor for `masked_fill` | Attention uses **additive float masks**. See [EXP-0011](EXP-0011.md). |
| `aten::lerp` falls back to the CPU inside AdamW | Optimiser step is partly host-bound; end-to-end throughput is below the matmul peak. |

## Interpretation

DirectML is a **viable GPU path for AMD hardware on Windows**, worth roughly 7–35x the CPU
for large matmuls. That ratio is the entire reason a real training run was possible here at
all. It is not a CUDA replacement: no fused kernels, no bf16 matmul, partial host fallback.

None — this experiment defined the project's precision and masking strategy.
