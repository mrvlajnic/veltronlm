# EXP-0006 — Tokenizer training and compression measurement

**Date:** 2026-09-30
**Status:** COMPLETE

## Question

Can a byte-level BPE be trained on this corpus that handles Serbian in both scripts,
code, JSON and markdown without losing round-trip fidelity?

## Method

`scripts/train_tokenizers.py` — stratified 9,380,105-character sample, two vocabularies.

## Result

### Compression (chars/token, measured on raw corpora)

| Slice | `tok-mini-32k` | `tok-4b-64k` |
|---|---:|---:|
| English prose | 3.788 | 3.788 |
| Serbian Cyrillic | 3.484 | 3.484 |
| Serbian Latin | 2.346 | 2.346 |
| Python source | 4.032 | 4.032 |
| Technical markdown | 3.826 | 3.826 |
| JSON / structured | 3.597 | 3.597 |
| **Round-trip failures** | **0** | **0** |

### The 64k vocabulary saturated at 57,611

At `min_frequency=2`, a 9.4 Mcharacter sample does not contain 65,536 distinct merges. The
4B model declares `vocab_size=65536`, leaving **7,925 unused embedding rows (12.1%)** —
97,145,856 dead parameters.

## Interpretation

**The two vocabularies are byte-identical on every slice.** That is a real result, not an
error: 9.4 Mcharacters does not distinguish a 32k vocabulary from a 64k one. Reporting the
64k tokenizer as "better compression" would be unsupported by these measurements.

**Serbian Latin costs 38% more tokens per character than English** and 133% more per word.
Serbian inflection plus the Latin/Cyrillic digraph problem splits the merge table's
capacity. Cyrillic (3.484) beats Latin (2.346) despite being the minority script, which
suggests digraph handling rather than inflection is the dominant cost.

**The Serbian Latin slice has 2 documents.** Too small to be statistically meaningful.
Treat 2.346 as indicative.

### Two real bugs found by the tests

1. **Non-ASCII was destroyed.** `fallback_byte_tokenizer` built its vocabulary as
   `chr(i) for i in range(256)` — Latin-1 — while byte-level decoding maps bytes through the
   GPT-2 `bytes_to_unicode` alphabet. Serbian round-tripped to `"    .  1  ."`.
2. **Every space vanished.** Installing the alphabet via `add_tokens` creates *added tokens*,
   which bypass pre-tokenization, so the whitespace split never mapped a literal space onto
   its `Ġ` symbol. Fix: install the alphabet as the BPE model's regular `vocab`.

## Next action

Retrain the tokenizers on a 4x larger sample (40 Mcharacters) to test whether the 32k/64k
distinction appears. Lower `min_frequency` to 1 and measure the overfitting cost.
