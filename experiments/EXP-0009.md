# EXP-0009 — Retrieval hybrid tuning

**Date:** 2026-09-30
**Status:** COMPLETE

## Question

How should lexical and vector signals be combined so that (a) documented questions retrieve
correctly and (b) unsupported questions are visibly unsupported?

## Method

14 held-out queries with known-correct document ids, plus nonsense queries as a negative
control. One variable changed per step.

## Result

### Final

| Metric | Value |
|---|---|
| **hit@1** | **14/14 = 100%** |
| **recall@3** | **14/14 = 100%** |
| Confidence, documented query | 0.88–0.97 |
| Confidence, nonsense query | 0.21–0.24 |

### The decisive change: absolute confidence

Rank fusion normalises so the top hit of **every** query scores 1.0, including a query that
matches nothing. Using it as a threshold meant escalation **could never fire**. Measured:
nonsense queries scored 0.90.

Fix: a separate absolute `confidence` = `0.70 * (bm25/bm25_max) + 0.30 * vec`, where `vec`
is a z-score across the candidate set, squashed and midpoint-subtracted so that "average"
contributes zero.

### Ablation log

| Step | Change | hit@1 | Nonsense-query confidence |
|---|---|---:|---:|
| 1 | BM25 + raw-cosine RRF | 5/12 | not measurable |
| 2 | Serbian→English expansion | 6/12 | not measurable |
| 3 | Vector z-scoring + 0.65/0.35 | 13/14 | 0.21 |
| 4 | Title/heading IDF boost | 13/14 | 0.21 |
| 5 | 0.70/0.30 weighting | **14/14** | **0.24** |

### Two more real bugs

* **Query rewriting deleted the subject.** `my VeltronHub X1 is not working` →
  `working, please help`, destroying the two most informative terms. Rewriting now strips
  filler only.
* **Taxonomy augmentation manufactured evidence.** The swallow question rose from 0.210 to
  0.725 purely because the intent classifier injected `specification dimensions compatible`.
  Confidence is now computed on the *rewritten customer query*, never the augmented one.

## Interpretation

Retrieval is solved for this corpus. What it does **not** establish: anything about a
50,000-document knowledge base, since this has 15 documents.

## Next action

Re-tune `MIN_RETRIEVAL_SCORE` per knowledge base; the current 0.18 is fitted to 15 documents.
