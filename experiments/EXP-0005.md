# EXP-0005 — Corpus acquisition and mixture

**Date:** 2026-09-30
**Status:** COMPLETE, with a large documented skew

## Question

How much permissively-licensed text can be acquired, and what mixture results?

## Method

`scripts/acquire_data.py`, `scripts/fetch_gutenberg_bulk.py`,
`scripts/crawl_wikipedia_categories.py`, then `scripts/build_dataset.py`.

## Result

| Source | Documents | Size |
|---|---:|---:|
| Gutenberg (catalog-derived) | 1,102 | 455.7 MB |
| CPython + Pallets + requests + urllib3 + NumPy | 161 | 6.08 MB |
| Wikipedia (curated + random) | 40 | 0.39 MB |
| Wikipedia categories | 17+ | 0.22 MB |
| Support KB | 15 | 0.02 MB |

Dataset `dataset-v1`: 1,380 documents seen, 1,312 kept (95.1%), 383,615,628 characters,
**19,485,297 train tokens**, 3.593 chars/token.

Achieved mixture matches targets exactly (0.34 general / 0.22 code / 0.12 technical /
0.12 sr / 0.10 literature / 0.10 support).

## Interpretation

### The corpus is 98.7% Project Gutenberg by character

378 of 384 Mcharacters. The resampling stage handles this — but it works on **document
counts**, and a Gutenberg document is ~360 KB while a Wikipedia article is ~7 KB. So the
achieved *token* fractions diverge from the document fractions.

Consequences, stated plainly:

* **377 repeats** of the general category, **116** of support, **165** of code, **138** of
  Serbian.
* The 15-document support knowledge base is **memorised**, not generalised. This is why the
  RAG layer, not model weights, carries domain behaviour.
* **Serbian is ~1% of the corpus** against a pool of 21 documents.

### Data acquisition was slower than expected

Wikipedia rate-limits anonymous clients (HTTP 429 after ~20 batched requests). The category
crawler managed only 17 documents in the time available. Fetching 1,102 Gutenberg books took
21 minutes and was rate-limit-free, which is why the corpus is literary.

## Failure

The first `acquire_data.py` run dispatched on the wrong key and every source wrote the
knowledge base instead — all four reported exactly 15 documents. Fixed and re-run with
`--force`; the fix is in the dispatch table, not a conditional.

## Next action

Serbian is the highest-value data gap. Options: a longer category crawl with exponential
backoff; Serbian Wikisource; a permitted parallel-corpus download.
