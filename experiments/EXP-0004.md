# EXP-0004 — 4B parameter accounting and feasibility

**Date:** 2026-09-30
**Status:** COMPLETE — verdict: **4B pretraining BLOCKED**
**Command:** `python scripts/verify_param_count.py`

## Question

Does the target architecture actually contain ~4B parameters, and can this host train it?

## Method

Two independent derivations, cross-checked on every run:

* **A** — analytic tensor shapes from `ModelConfig.param_counts()`
* **B** — real `nn.Parameter` objects instantiated on the `meta` device (no memory allocated)

## Result

### Parameter count

All 7 configurations: `analytic == meta`. The target:

| Component | Parameters | Share |
|---|---:|---:|
| Token embedding | 201,326,592 | 5.000% |
| Attention (q/k/v/o) | 905,968,896 | 22.500% |
| MLP (SwiGLU 3 x D x F) | 2,717,908,992 | 67.496% |
| All norms | 233,472 | 0.006% |
| LM head | 201,326,592 | 5.000% |
| **Total** | **4,026,765,312** | **100%** |

**4.027 B** — inside the 3.7 B–4.3 B target band.

### Feasibility: memory

| Tensor | Size |
|---|---:|
| fp32 params | 15.00 GiB |
| fp32 grads | 15.00 GiB |
| Adam m | 15.00 GiB |
| Adam v | 15.00 GiB |
| **Minimum optimizer state** | **60.00 GiB** |

Available: **~10 GiB** usable (measured; see docs/environment.md section 4b). Shortfall
**6.0x**, before activations or fragmentation. No
single-GPU sharding strategy closes a 5x gap.

### Feasibility: time

Chinchilla-optimal, 20 tokens per parameter:

```
tokens = 20 x 4.03e9 = 8.06e10
FLOPs  = 6 x 4.03e9 x 8.06e10 = 1.95e21
```

| Assumption | Time |
|---|---:|
| Raw matmul peak (2.80 TFLOP/s), 100% model FLOPs utilisation | **~22 years** |
| Measured training efficiency (3,600 tok/s) | **~710 years** |

### Feasibility: inference

| Precision | Weights | Fits 12 GiB | KV cache @8k, bs=1 |
|---|---:|---|---:|
| fp32 | 15.00 GiB | no | 1.125 GiB |
| bf16/fp16 | 7.50 GiB | **yes** | 1.125 GiB |
| int8 | 3.75 GiB | **yes** | 1.125 GiB |
| int4 | 1.88 GiB | **yes** | 1.125 GiB |

## Interpretation

The architecture is real, correctly sized, and serviceable at 4B. **From-scratch 4B
pretraining is blocked by two independent, individually decisive limits.** Neither is close.

This is reported as a blocker with arithmetic, not as an excuse. The correct response was
to build everything and train the largest tier that fits, which is what
[EXP-0008](EXP-0008.md) does.
