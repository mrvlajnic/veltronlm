## Question

Can the full pretraining pipeline run end to end on consumer AMD hardware, produce a
monotonically falling loss curve, checkpoint resumably, and stay numerically stable?

### Interpretation

**Validation loss fell 5.762 → 5.101 (perplexity 317.9 → 164.3) over 500 steps.** The
initial loss of 9.55 matches `ln(32768) = 10.397` within the expected range for a
zero-initialised output projection, confirming the model starts near-uniform.

**Train and validation loss track each other closely** (step 500: 4.56 train, 5.10 val).
The 0.55 nat gap is the expected generalisation gap, not memorisation — with 19.5M tokens
against 8.2M consumed, the model has seen ~42% of the corpus once.

**Grad norm declined from 2.60 to ~0.55** and stayed bounded. No instability, no spikes, no
NaN. Clipping at 1.0 engaged only in the first ~120 warmup steps.

**Absolute loss remains high** (5.1 nats ≈ perplexity 164 over a 32k vocabulary). That is
expected at this scale: the model is 55.7M parameters, 33.5M of which are the embedding and
output matrices, leaving ~22M non-embedding parameters, and it has seen 8.2M tokens against a
Chinchilla-optimal ~1.1B. A factor of ~130 short of compute-optimal.

## What this experiment does and does not establish

**Establishes**

* The pretraining loop trains stably on consumer AMD hardware via DirectML.
* The loss curve falls monotonically and the gradient norm stays bounded.
* Checkpointing, rotation and validation all work in a live run.
* Measured throughput for a future compute estimate.

**Does not establish**

* That the model is competent. At perplexity 164 it is far from useful for open-ended
  generation.
* Anything about the 4B architecture beyond what [EXP-0004](EXP-0004.md) covers.
* Any comparison with another model. No baseline was run.
