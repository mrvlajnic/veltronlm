# EXP-0012 — Chunked cross-entropy for memory-bounded loss

**Date:** 2026-09-30
**Status:** COMPLETE

## Question

Can the training loss be computed without materialising a `batch x seq x vocab` fp32
log-softmax buffer?

## Method

Added `chunk_tokens` to `VeltronLM.compute_loss`, accumulating the loss over slices of the
flattened token dimension.

## Result

### The failure it fixes

At micro-batch 4, seq 1024, vocabulary 32,768:

```
RuntimeError: Could not allocate tensor with 1609301920 bytes.
There is not enough GPU video memory available!
```

### After chunking

| Micro-batch | Before | After |
|---:|---|---|
| 8 | OOM (3.22 GB) | — |
| 4 | OOM (1.61 GB) | **works** |
| 2 | works | works |

Equivalence: chunked and unchunked losses agree to **< 1e-4** (`test_chunked_loss_matches_unchunked`).

## Interpretation

This is not a micro-optimisation. At 4B scale with a 65,536 vocabulary and 8,192-token
context, the undivided logit tensor alone is ~2 GiB per micro-batch, and the fp32 softmax plus
its backward multiply that by two to three. Chunking bounds it at `chunk_tokens x vocab`.

Combined with [EXP-0011](EXP-0011)'s additive masks, this is what makes the 4B architecture
*trainable in principle* — the memory requirement still exceeds this host, but the blocker is
now a hardware limit rather than an implementation gap.
